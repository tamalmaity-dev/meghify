# v0.2.1 — GitHub sources in the project flow

**Released:** 2026-10-17 · **Commit:** [`2b017d0`](https://github.com/tamalmaity-dev/meghify/commit/2b017d0) · **Tag:** `v0.2.1`

Fixes the resource chooser so a project's GitHub picker lists your GitHub
sources even before an installation appears, instead of dead-ending on an empty
state.

## Update

```bash
meghify update
```

or re-run the installer. Interface change only — no schema or database changes.

## What changed

### Choose GitHub App now lists sources

**New resource → Git Repository (with GitHub App)** now shows every GitHub App
connected to the panel, exactly like the Sources page:

- a registered source lists the accounts it is installed on — click one to load
  its repositories;
- a source that has no installation yet offers **Install on GitHub** — grant
  access over there, come back and press **Refresh**;
- a source that never finished setup links straight to **Finish setup**;
- **New GitHub App** opens the creation dialog right in the flow — the same
  dialog and manifest walkthrough as Sources, no need to detour there first.

Previously this step only listed installations, so a registered source that had
not been installed yet — or one installed moments ago but not yet synced —
looked like an empty panel state with no way forward.

### Under the hood

- The **New GitHub App** dialog is now a shared component
  (`web/src/components/github-app-dialog.tsx`) used by both the Sources page and
  the project chooser.
- The installation callback resolves the source from the id carried in install
  links before probing every app, so recording a new installation needs fewer
  GitHub API round-trips.
- The chooser surfaces loading and error states for its source and installation
  queries instead of silently rendering them as empty.
