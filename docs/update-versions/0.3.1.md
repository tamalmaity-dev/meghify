# v0.3.1 — live build logs, our own helper image, sslip.io domains

**Released:** 2026-10-17 · **Commit:** [`850dd3a`](https://github.com/tamalmaity-dev/meghify/commit/850dd3a) · **Tag:** `v0.3.1`

Build output now streams live into the log viewer, deployments run on Meghify's
own helper image, and applications get an automatic address on registration.
Builds are also gentler on small servers.

## Update

```bash
meghify update
```

or re-run the installer. No schema changes.

## What changed

### Build logs are live again

The log viewer updated only on refresh because three defects stacked up:

- the SSE hub was mounted at `/stream` while the viewer called `/api/stream`;
- the stream sat outside the session gate, so it should never have been
  reachable anonymously — it now requires a login like every other API; and
- the client read the SSE envelope without unwrapping its `payload`, so even
  delivered lines were dropped.

All three are fixed: build output appears line by line as the build runs, and
refresh/find/download keep working on the stored log.

### Our own helper image

Deployments no longer pull Coolify's helper image. Every release now publishes
**`ghcr.io/tamalmaity-dev/meghify-helper:<version>`** (and `:latest`) for
amd64, arm64 and armv7 — Alpine plus git, nixpacks, railpack, and the docker
CLI with buildx and compose. The panel defaults `BUILD_HELPER_IMAGE` to the
tag matching its own version; set it to pin a different image.

### Builds are lighter

- `BUILD_CONCURRENCY` (default **1**) — only one deployment builds at a time;
  a deployment that has to wait writes *"waiting for another build to finish"*
  to its log. This is what kept the CPU graph pinned when several builds
  overlapped.
- `BUILD_CPU_LIMIT` / `BUILD_MEMORY_LIMIT` — optional ceilings for each
  helper container (`1.5`, `512m`, `2g`).

### Automatic domains

Applications created without a domain now get one:
`<name>-<id>.<server-ip>.sslip.io` over plain HTTP. sslip.io resolves the
embedded IP, so the app is reachable with zero DNS setup — exactly the address
Coolify shows. Replace it with a real domain any time in the Domains section.
Applications from earlier releases get theirs backfilled on the first deploy.
