# v0.3.0 — helper-container builds, server workspace, deployment history

**Released:** 2026-10-17 · **Commit:** [`44c298a`](https://github.com/tamalmaity-dev/meghify/commit/44c298a) · **Tag:** `v0.3.0`

Fixes deployments failing with *"nixpacks is not installed on this node"* —
builds now run inside a disposable helper container, the same model Coolify
uses — and turns the Servers section into a full workspace with a terminal.

## Update

```bash
meghify update
```

or re-run the installer. Migration `003_nodes` is additive: it adds the
server's description, architecture and boot time, and backfills the default
server's description.

## What changed

### Builds run in a helper container (the fix)

The panel image is deliberately minimal; previously nixpacks builds relied on
a binary on the host, which most servers don't have. Now every deployment
starts a one-shot helper container — with the engine socket mounted — and runs
**git clone, nixpacks/railpack, `docker build` and `docker compose` inside
it**:

- the host needs only Docker; nixpacks is never installed on it;
- clone credentials are redacted from build logs;
- the helper is named `meghify-builder-…` and removed when the deployment ends;
- if the helper image can't be pulled, the panel falls back to host tools, so
  older installs keep working.

The image is configurable: `BUILD_HELPER_IMAGE` (default
`coollabsio/coolify-helper:1.0.17`).

Two latent pipeline bugs were fixed along the way: the auto-build image tag
was computed twice (so it changed while a long build ran, and the release step
looked for the wrong tag), and the application network was created after the
container that attaches it — which broke the first deploy of an application.

### Servers workspace

The server list rows now open a detail page laid out like Coolify's:

- **General** — a *Server overview* card with the engine's facts (operating
  system, architecture, kernel, CPU cores, memory, Docker version, up since,
  last seen), a **Ready** badge and one-click **Validate Connection**, plus an
  editable **Connection** card (name, description, address, SSH user/port).
- **Terminal** — an interactive shell on the server: SSH for remote servers, a
  helper container with the docker CLI for the panel's own machine.
- **Metrics** — the same live charts the dashboard shows, per server.
- **Danger zone** — removal, with an explanation instead of a button on the
  default server.

The **default server** (the machine the panel runs on) is now protected: the
API refuses to delete it with a 409 and the UI explains why. Its facts are
discovered from the Docker engine instead of the container's own `/etc` files.

### Deployments UI

The application page's history is now a proper deployment table — searchable,
with status dots, source (Manual/Webhook), commit SHA and message, start time,
duration and the server it ran on. Picking a row opens its build output with
**find-in-logs**, **download**, **refresh** and Coolify-style line colours
(failures red, successes green, warnings amber).
