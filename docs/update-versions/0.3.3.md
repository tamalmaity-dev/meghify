# v0.3.3 — rolling redeploys, runtime logs, Actions menu

**Released:** 2026-10-17 · **Commit:** [`319ef93`](https://github.com/tamalmaity-dev/meghify/commit/319ef93) · **Tag:** `v0.3.3`

Redeploying now works: the replacement container starts beside the running
one, waits for its health check, retires the old container and takes over the
application's name — a true rolling update. The application page gains
Coolify's **Actions** menu and a live **Runtime logs** view.

## Update

```bash
meghify update
```

or re-run the installer. No database changes.

## What changed

### Rolling redeploys (the fix)

A second deployment failed with *"container name /meghify-… is already in
use"*: the release step created the replacement under the same name the
running container already owned. The pipeline now:

1. creates the replacement under a temporary name **beside** the old container,
2. starts it and waits for its health check,
3. stops and removes the previous container,
4. renames the new container into the application's stable name (so the
   terminal, logs, restart and stop keep finding it).

Nothing is replaced unless the new container is healthy, and there is no
window without a running container.

### Actions menu

The header now carries an **Actions** dropdown like Coolify's — **Redeploy**,
**Redeploy (without cache)**, **Restart**, **Stop** — and the primary button
reads *Redeploy* once the application has a deployment.

### Runtime logs

A new **Runtime logs** section streams the container's stdout/stderr live
(**Stream live** toggle), with a tail selector (100 / 500 / 2000 / all),
find-in-logs, reload and download. The stream's demultiplexer carries partial
frames across reads, so long follow sessions stay clean.

### Domain visibility

The deployment log lists the addresses the release serves
(`[*] domains: http://…sslip.io`), and the application header links the
automatic domain over the scheme it actually uses (HTTP for sslip.io).
