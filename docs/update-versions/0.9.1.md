# v0.9.1 - Port routing and post-deploy refresh

**Released:** 2026-10-22 - **Tag:** `v0.9.1`

This patch fixes two field reports from v0.9.0: an application header that kept
showing `idle` and `no image yet` after a successful deployment, and a domain
answering Traefik's `502 Bad Gateway` after the application's container port
was changed.

## Update

```bash
meghify update
```

No migration is required. The panel keeps the existing v0.9.0 Resource Guard
settings and history.

## Post-deploy status refresh

The deployment list was polled while a build ran, but the application row was
not refreshed when it finished. The page could therefore keep the `idle` status
and empty image tag it had cached when the deployment was queued, even though
the backend had already recorded both `running` and the new image.

The application view now reloads its status and image when the latest
deployment reaches `success`, `failed` or `canceled`.

## Container port and domain routing

A domain with no explicit **Internal port** follows the application's
**Container port**. Two mistakes could leave the route on the wrong port:

- saving a domain materialised the application port as a fixed override;
- changing the application port did not update such an override.

Now:

- leaving the domain port empty inherits the application port;
- saving the application's current port as a domain port also stores it as
  inherited;
- changing the application port clears domain overrides that repeated the old
  port, while deliberately different per-domain ports are preserved;
- the deployment passes the application's **Container port** as `PORT` unless
  the app already defines `PORT`. Common Node, Next.js, Rails and .NET
  runtimes then listen on the same port the proxy targets.

The Networking and Domains cards explain that container ports are isolated per
application, so two apps can both use 3000. A process with a hard-coded port
must still match **Container port**; the Runtime logs show the actual listening
port.

If a domain still answers `502 Bad Gateway`:

1. confirm the app listens on `0.0.0.0`, not only `127.0.0.1`;
2. set **Networking -> Container port** to the port printed in the Runtime
   logs;
3. redeploy so the container is recreated with the new port and `PORT` value.

## Validation

- `go test -count=1 ./...`
- `go vet ./...`
- `go build ./...` and `go build -tags web_assets ./...`
- `npm run typecheck` and `npm run build`

Docker runtime validation remains limited to hosts with a Docker daemon.
