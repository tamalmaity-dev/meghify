# v0.5.0 — Coolify-style domains

**Released:** 2026-10-17 · **Commit:** [`1a6425e`](https://github.com/tamalmaity-dev/meghify/commit/1a6425e) · **Tag:** `v0.5.0`

The Domains card becomes the full Coolify experience — per-domain protocol,
internal port and path; HTTP→HTTPS redirects; search-indexing toggles; DNS
checks with a status per row — and the generated proxy labels now match
Coolify's per-domain router layout.

## Update

```bash
meghify update
```

or re-run the installer. Migration `005_domains` is additive.

## What changed

### Domains card

- **Search**, **Check All DNS**, and an **Add Domain** dialog with Protocol /
  Domain / Port / Path — and **Generate Domain** proposing the automatic
  sslip.io address.
- Per row: **Protocol redirect** (`HTTP → HTTPS` for TLS domains, otherwise
  Disabled), **Domain redirect** (reserved, Disabled), **Internal port**
  (per-domain override), **Search indexing** toggle, **DNS status**
  (*DNS matches* / *DNS mismatch* / *Not checked*), and actions: check, edit,
  remove.
- The **Redirect HTTP to HTTPS** switch at the top applies to the
  application's domains.
- DNS checks resolve the hostname and compare it with the server's public
  address; the result is stored on the row.

### Per-domain proxy labels (Coolify layout)

Each domain now produces a router pair — `http-<app>-<n>` / `https-<app>-<n>`
— with its own service, exactly like Coolify:

- `gzip` compression on every router;
- `redirect-to-https` on the plain-HTTP companion of TLS domains;
- `letsencrypt` certificate resolver when `ACME_EMAIL` is set;
- the domain's `PathPrefix` in the rule;
- an `X-Robots-Tag: none` middleware when search indexing is off.

The proxy's entrypoints are now named `http`/`https` (were `web`/`websecure`)
to match.

Re-deploy the application to attach label changes to the running container.
