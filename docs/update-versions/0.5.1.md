# v0.5.1 — two-step delete with cleanup

**Released:** 2026-10-17 · **Commit:** [`c040a39`](https://github.com/tamalmaity-dev/meghify/commit/c040a39) · **Tag:** `v0.5.1`

Deleting an application now follows Coolify's guard rails and cleans up what
it leaves behind.

## Update

```bash
meghify update
```

or re-run the installer. No schema changes.

## What changed

### Two-step delete

The Danger zone's **Delete application** opens the Coolify flow:

1. **Cleanup options** — permanently delete volumes, remove non-predefined
   networks, delete configuration files from the server, and run Docker
   cleanup (unused images and builder cache). All ticked by default.
2. **Confirmation** — a warning banner, the list of actions that will run,
   the resource name with a copy button, and a **Resource name** field.
   *Continue* stays disabled until the name is typed exactly.

### What DELETE actually cleans

`DELETE /applications/{id}` with the selected options:

- stops and removes the application container;
- deletes the volume records and — when selected — their host directories
  (system paths are never touched) plus the private `meghify-<app>` network;
- removes the deploy workspace under `DATA_DIR/workspaces/<id>`;
- with Docker cleanup: dangling images, the builder cache, and the
  application's own built image tags.

The API answers with a summary — `volumesRemoved`, `networkRemoved`,
`configRemoved`, `spaceReclaimed` — so the UI can report what happened.
