# 0.6.3 — Docker disk usage and storage cleanup

## Why

A single application with two builds could push a small VPS near its disk
ceiling, with nowhere to look and nothing to press. Three things grew without
bound:

- **Every release left a freshly stamped image behind.** Each build tags
  `meghify.local/<app>:<id>-<stamp>` and nothing removed old ones — the e2e
  environment alone collected 27 tagged images from a three-line app.
- The **build cache inside the build sandbox** (the `meghify-build-cache`
  volume) saved every layer every build produced, forever.
- **Failed builds** leave untagged image leftovers on both engines.

## What's new

### Docker disk usage card (dashboard)

The dashboard now explains where the bytes went, the way Dokploy's monitoring
does: a donut of the engine's **images, build cache, volumes and containers**
(`docker system df` accounting), the same decomposition from **inside the
build sandbox** when it is running, and a **largest items** list naming the
specific images, volumes and containers behind the totals. Refreshes on the
minute, or on demand.

### Free up space

The card carries a cleanup button (and the panel owns it as
`POST /api/docker/cleanup`): it reclaims dangling images, keeps only the
newest `IMAGE_KEEP` images per application repository, prunes the build cache
back to `BUILD_CACHE_KEEP`, and does the same inside the sandbox — all with
running containers' images protected.

### The bleed is fixed at the source

- **Right after every successful release** the pipeline trims the
  application's image repository down to the two newest tags, so deploys
  themselves no longer accumulate (the hourly `gc` job re-checks anyway).
- **`IMAGE_KEEP`** (default `2`) sets how many release images per application
  a cleanup keeps. The running container's image always survives.
- **`BUILD_CACHE_KEEP`** (default `8g`) bounds the build cache on the engine
  and inside the sandbox; exceeded, the next cleanup prune keeps only the most
  recently used records. Set it to `0` to leave the cache unbounded, `2g` on a
  8 GB box if Docker storage is tight.

## Updating

```bash
meghify update
```

The first cleanup pass after boot may log a `docker cleanup reclaimed
storage` line — on boxes that ran earlier releases this frees the images and
cache slack at once. Nothing else changes: domains, releases and certificates
carry over untouched.
