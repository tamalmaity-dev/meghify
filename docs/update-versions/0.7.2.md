# v0.7.2 - drop the previous image, keep only what is running

**Released:** 2026-10-21 · **Tag:** `v0.7.2`

This patch makes image cleanup match the intent of **Free up space**: old
panel-built images, superseded proxy versions and retired helpers are removed,
while images used by a container are always kept.

## Update

```bash
meghify update
```

No schema changes.

## Why two application images were kept

Every deployment produces a new image tag:

```text
meghify.local/roopsa-web:5226b772-...
meghify.local/roopsa-web:bf50f017-...
```

`IMAGE_KEEP` defaulted to **2**, so cleanup intentionally kept the previous
image for rollback. The second image in **Largest items** was not being served
by anything. The default is now **1**: the newest image and the image of the
running (or stopped) container survive; older tags are removed.

Only images stamped by the panel (`meghify.application`) are part of this
sweep. An image you pulled yourself is not touched.

If your `.env` explicitly sets `IMAGE_KEEP=2`, it will continue to retain one
previous image. Change it to `1` to get the new default behavior:

```bash
IMAGE_KEEP=1
```

## Why both Traefik versions were kept

`traefik:v3.3` was left from an older panel generation, while
`traefik:v3.7` is the current proxy. The old version was within the old
two-image retention window. Cleanup now keeps exactly the configured
`PROXY_IMAGE` tag and removes other tags in that repository. Docker refuses to
remove a version still referenced by a running or stopped container.

## Automatic cleanup

The same pass runs automatically:

- about 20 seconds after the panel starts,
- after every successful release (application image trim), and
- in the hourly `gc` background job.

**Free up space** runs it immediately. After this update, startup cleanup should
remove the old application image and `traefik:v3.3`.

## Image names that are not stale

These are current runtime images, not old copies:

- `docker:27-cli` - the on-demand terminal helper for the local server.
- `docker:29-dind` - the build sandbox daemon.
- `meghify-build-cache` - the sandbox's disk build cache (7.5 GB here), not an
  image and not RAM. It is bounded by `BUILD_CACHE_KEEP` (default `8g`).

Stopping or removing those would break the terminal or the next build. The
build cache can be trimmed with **Free up space** or by lowering
`BUILD_CACHE_KEEP`.

`go test -count=1 ./...`, `go vet ./...`, `go build ./...`, `go build -tags
web_assets ./...`, `npm run typecheck` and `npm run build` pass. Docker runtime
