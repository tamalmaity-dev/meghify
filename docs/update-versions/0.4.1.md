# v0.4.1 — the proxy that makes domains work

**Released:** 2026-10-17 · **Commit:** [`9f40afe`](https://github.com/tamalmaity-dev/meghify/commit/9f40afe) · **Tag:** `v0.4.1`

Fixes the three things your last deployment exposed: the automatic domain
timed out because nothing was actually proxying it, the application page said
*"no image yet"* after a successful build, and the deployment log showed its
output twice.

## Update

```bash
meghify update
```

or re-run the installer. No schema changes.

## What changed

### The reverse proxy is now really deployed

Applications with domains get a Traefik instance the panel ensures on the
shared `meghify` network: the deployment starts `meghify-proxy`, joins the
application to that network and the routing labels do the rest. Docker-compose
installs shipped Traefik already; **systemd installs had none** — which is
exactly why the sslip.io address timed out.

- default image is **`traefik:v3.7`** — Traefik v3.5 and older default to
  Docker API 1.24, which Docker Engine 29 (your server) refuses outright;
- `PROXY_IMAGE` swaps the image (empty disables proxy management);
- `PROXY_HTTP_PORT` / `PROXY_HTTPS_PORT` (default 80/443) let Meghify coexist
  with an nginx that already owns those ports;
- `ACME_EMAIL` enables Let's Encrypt for TLS domains;
- if the proxy cannot start, the deployment still succeeds and the log says
  why.

Open ports 80 and 443 (or your chosen alternates) in the server firewall for
domains to be reachable.

### "no image yet" fixed

Every successful release now records the produced image tag on the
application, so the page shows what is actually running.

### No more duplicated deployment logs

The live-log stream replayed its buffered history on connect, and the viewer
had already loaded the durable log — so everything appeared twice. The viewer
now asks for the live tail only (`replay=0`); refreshing still replays the
complete stored log.
