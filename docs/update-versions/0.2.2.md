# v0.2.2 — repository picker fixed, Coolify-style flow complete

**Released:** 2026-10-17 · **Commit:** [`5f7d8ca`](https://github.com/tamalmaity-dev/meghify/commit/5f7d8ca) · **Tag:** `v0.2.2`

Fixes the blank repository rows in the GitHub picker — names, clone URLs and
default branches were dropped between GitHub and the browser — and finishes the
add-resource flow with an inline build configuration step.

## Update

```bash
meghify update
```

or re-run the installer. Interface and API-shape fix only — no schema or
database changes.

## What changed

### Repository picker fixed

The panel speaks GitHub's own payload shape (`full_name`, `clone_url`,
`default_branch`) and passed it straight through to the browser, which reads
camelCase. Every repository row therefore rendered blank — and clicking one
crashed on `fullName.split`. The API now translates the repository list before
it leaves the panel, so the picker shows `owner/name`, the default branch and
the private/archived badges, and the application form prefills correctly from
the pick.

### Build configuration step

Picking a repository now continues the way Coolify walks through it:

- a **Repository** card showing the picked repository (with **Change
  repository** to switch);
- a **Build configuration** card — name, branch, build pack
  (Nixpacks/Railpack/Dockerfile), base directory, container port, health check
  path, and **Deploy automatically on every push** — all prefilled from the
  repository;
- **Create** in the card header instead of the generic modal.

### Sources page

The source list is now a searchable grid of cards: a green **Connected** badge
once the app is installed, **Not installed** when it is registered but no
account has installed it yet, and **Setup incomplete** until GitHub issues the
credentials — with the installations, Install action and removal still on each
card.

### Source details

Each configured source gained a **General** card in the style of GitHub's own
app settings: App ID, installation ids, HTML URL, API URL and Client ID, with
the webhook secret and private key shown as sealed, plus an **App settings on
GitHub** link and a **Connected** pill in the header.

## Under the hood

- The API layer translates `github.Repository` into a camelCase wire view; a
  unit test and an e2e that points a source at a stub GitHub server (Enterprise
  base URL on localhost) lock the shape in.
- The project chooser keeps its state machine (`apps → repos → configure`), so
  switching repository or leaving the flow never strands the form.
