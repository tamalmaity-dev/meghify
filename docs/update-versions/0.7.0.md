# v0.7.0 - security hardening, remote servers, and durable resources

**Released:** 2026-10-21 · **Commit:** [`10bbf81`](https://github.com/tamalmaity-dev/meghify/commit/10bbf81) · **Tag:** `v0.7.0`

This release closes the non-database findings from the code review. The theme
is trust boundaries: the panel now distinguishes administrators from members,
scopes automation tokens, pins SSH host keys, and stops treating user-supplied
host paths as Docker mounts. Remote servers are fully wired into deployment,
routing, teardown, terminal access and metrics.

## Update

```bash
meghify update
```

Docker Compose installs can rebuild from the new tag in a checkout:

```bash
git fetch --tags
git checkout v0.7.0
docker compose up -d --build
```

The new migration only adds `nodes.host_key_fingerprint`; it is applied
automatically on boot.

## Read before updating

- **`AUTH_SECRET` is required in production.** The panel no longer generates an
  ephemeral key on every boot, because that silently breaks stored SSH keys,
  environment variables and TOTP seeds. Installer/Compose deployments already
  generate one. If you run the binary directly, set it before restarting. The
  error message includes the `openssl rand -hex 32` command.
- **Members can no longer mutate infrastructure.** They can read applications
  and deploy, restart, stop, inspect and access logs for existing applications.
  Applications, domains, environment variables, volumes, services, servers,
  SSH keys, GitHub sources, projects, environments, jobs, databases and users
  are administrator-only.
- **Host bind mounts are replaced by named Docker volumes.** The panel no
  longer accepts or deletes arbitrary host paths. Existing volume records are
  not copied into the new named volumes; if an application stores data in a
  bind mount, back it up and copy it into the new volume before redeploying.
  The old host directory is left untouched.
- **SSH host keys are pinned on first use.** Existing nodes have no pin yet, so
  the next successful connection records it. For a first connection across an
  untrusted network, paste the server's SHA256 fingerprint into the form.
- **Backup jobs now fail visibly.** Database backup artifacts are not
  implemented in this release. Jobs end in an explicit error instead of
  remaining "running" forever.

## Security and access control

- Admin guards cover users, teams, servers, SSH keys, Docker cleanup and disk
  usage, jobs, GitHub sources, services, projects, environments, databases,
  application configuration, both terminals, and all infrastructure mutations.
- API tokens enforce `read`, `write`, `deploy` and `admin` scopes. Empty scopes
  retain the owner's full privileges for backwards compatibility. Scoped tokens
  cannot mint new tokens, and token revocation is restricted to the owner.
- Login is rate-limited per account and per source address. `TRUST_PROXY`
  controls whether `X-Forwarded-For`/`X-Real-IP` are trusted; leave it off when
  clients connect directly.
- TOTP seeds are sealed with `AUTH_SECRET`; legacy plaintext seeds are migrated
  on first use. Login now returns a distinct `totp_required` challenge, and
  enabling or disabling 2FA rotates all other sessions.
- The last administrator cannot be demoted or deleted. Passwords use Argon2id
  and password changes preserve existing 2FA enrollment.
- Removed unrestricted `middleware.RealIP` handling. WebSocket terminals now
  use same-origin checks, and SSE channels are restricted to deployment,
  application and node IDs.

## Remote servers

- Every Docker operation resolves the client for the resource's node instead
  of falling back to the local engine: deployments, rolling releases, routes,
  restart/stop/logs/terminal, database lifecycle, services, recovery and
  maintenance.
- Applications, services, databases, projects and environments share node-aware
  teardown. Compose application stacks are brought down explicitly because
  their containers do not carry panel labels.
- Remote routing is uploaded, reconciled and cleared on the target node. Remote
  servers report CPU, memory, disk and network samples over SSH once a minute.
- SSH host keys are verified after the first connection. A mismatch is rejected
  with both fingerprints, and changing a node's address clears the old pin.
- A server cannot be deleted while applications, services or databases still
  reference it.
- Non-admin global search no longer returns server records.

## Resource lifecycle and build safety

- Application containers, networks, compose projects, routes, databases,
  database volumes and services use immutable record IDs for engine names, so
  renames cannot collide with another resource.
- Persistent application storage uses named Docker volumes. Volume deletion
  targets the engine-side named volume; no client-provided host path is stored
  or deleted.
- Repository-relative `baseDirectory` and Dockerfile paths are validated at the
  API and again before builds. Absolute paths, drive letters, backslashes and
  `..` traversal are rejected.
- Deployment logs are capped at 50 MiB and retained for 30 days. Logs are
  deleted with their application/service records. Slow SSE consumers are
  dropped without leaking their goroutines.
- Interrupted `running` jobs are requeued at startup; retries of active jobs are
  rejected, and canceled or finished deployments are never restarted.
- Application PUT/PATCH now has partial-update semantics, so one card cannot
  overwrite unrelated fields. Route configuration is resynchronized after
  updates and domain changes.
- Service deployments run `docker compose up -d` through the helper image with
  a local host fallback; deletion runs compose-down and removes panel-side
  compose/log files.

## UI

- Role-aware navigation and dashboard cards; member-facing project, application
  and infrastructure controls are hidden or read-only.
- New Settings flows for 2FA enrollment/confirmation/disable, password change,
  and scoped API-token creation with a visible one-time token.
- New Team page for user creation and role management.
- Application, node and domain views show engine-derived names and remote-node
  targeting. GitHub Enterprise base URLs are formatted correctly.

## Deferred

PostgreSQL, provisioned-database connectivity, real backup dumps/uploads and
scheduled backup execution remain deferred. The README and `.env.example` no
longer advertise them as working.

## Verification

`gofmt`, `go build ./...`, `go build -tags web_assets ./...`, `go vet ./...`,
`go test -count=1 ./...`, `npm run typecheck` and `npm run build` pass. Docker
image creation, Compose startup, socket-group behavior and a live remote-node
deployment still need a Docker-capable host and are not validated by CI.
