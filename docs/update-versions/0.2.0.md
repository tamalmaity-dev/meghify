# v0.2.0 — GitHub Apps

**Released:** 2026-10-17 · **Commit:** [`fd030a4`](https://github.com/tamalmaity-dev/meghify/commit/fd030a4) · **Tag:** `v0.2.0`

Connect GitHub to the panel with a GitHub App — the same model Coolify and
Dokploy use — and deploy public or private repositories straight from a
repository picker, with automatic redeploys on every push.

## Update

```bash
meghify update
```

or re-run the installer. The schema change is additive: existing
applications, projects and databases are untouched.

## What's new

### Sources

A new **Sources** entry in the sidebar lists the GitHub Apps connected to this
panel. Each app shows whether setup finished, which accounts installed it, and
gives one-click **Install** and **Refresh** actions.

### Create the app from the panel

**Add GitHub App** opens a dialog for the app name, an optional organization and
the GitHub host (`github.com`, or a self-hosted GitHub Enterprise server). The
panel writes the source first, then walks you through GitHub's manifest flow:

1. the setup page shows the webhook endpoint and the permissions the app needs
   (Contents `read`, Metadata `read`, Email addresses `read`);
2. **Register With GitHub** opens GitHub's confirmation page — one click creates
   the app, generates its private key and webhook secret, and returns to the
   panel, which stores the credentials sealed with the panel's encryption key.

An **Advanced** card covers manual setup: create the app on GitHub yourself and
paste its App ID, private key and webhook secret; the panel verifies the key
before storing anything.

### Repository picker

In a project, **New resource → Git Repository (with GitHub App)** adds a
two-step chooser:

1. **Choose GitHub App** — pick the installing account (user or organization);
2. **Choose a repository** — search the repository list GitHub returns,
   including private ones.

The application form opens prefilled with the repository, its default branch
and **Deploy automatically on every push** checked.

### Push-to-deploy webhooks

- GitHub delivers `push` events to `POST /api/webhooks/github`; every delivery
  is verified against the app's webhook secret with `X-Hub-Signature-256`, so
  the endpoint can safely stay outside the login gate.
- Pushes to the branch an application tracks queue a deployment that records the
  commit SHA and message. Other branches, tags and pushes while a build is
  already running are ignored.
- The **Source** card on the application page shows the repository and has a
  per-application **Deploy on every push** toggle.

### Private repositories

Clones authenticate with GitHub App installation tokens that are **minted fresh
for every git operation** (one hour lifetime) and never written into the
workspace's `.git/config`. No deploy keys or stored SSH credentials needed.

## Under the hood

- `internal/github`: REST client, hand-rolled RS256 app JWT (no new
  dependencies), manifest builder and webhook signature verification.
- Migration `002_github`: adds `github_apps`, `github_installations` and the
  application link columns (`github_app_id`, `github_installation_id`,
  `repository_full_name`, `auto_deploy`).
- The manual deploy endpoint and the webhook share one queueing path, so both
  enforce the same one-build-at-a-time rule.

## Notes

- GitHub must be able to reach the panel's public URL. Plain HTTP works, but
  GitHub recommends HTTPS; check **GitHub → your app → Advanced → Recent
  Deliveries** after a push to confirm deliveries arrive with a 2xx response.
- Removing a source keeps applications and their deployment history — it only
  disables automatic deploys and drops the installation link.
