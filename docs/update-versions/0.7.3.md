# v0.7.3 - stop the idle build sandbox, leave a fresh host on uninstall

**Released:** 2026-10-21 · **Tag:** `v0.7.3`

This patch reduces idle memory, removes orphaned application images left by an
older or deleted application, and makes `meghify uninstall` clean up everything
Meghify created.

## Update

```bash
meghify update
```

No schema changes.

## Why 1.2 GB was in use

The dashboard's memory number is **host-wide**, not the memory of one project.
It includes the operating system, the Docker daemon, the panel, Traefik, the
application container, and the Docker-in-Docker build sandbox. The sandbox is
the large avoidable part: its daemon and cache metadata stayed resident long
after a build finished.

The sandbox is now stopped automatically:

- at panel startup, when no build can be running, and
- after `BUILD_SANDBOX_IDLE_TIMEOUT` (default **15m**) without a build.

The next deployment starts it again and keeps using the
`meghify-build-cache` volume, so this is not a cold rebuild. Set
`BUILD_SANDBOX_IDLE_TIMEOUT=0` if you prefer to keep it running continuously.
The exact memory drop depends on the application and Docker version; use
`docker stats --no-stream` to see the remaining per-container usage.

## Orphaned application images

An application that was deleted while the Docker engine was unreachable could
leave a stopped container behind. That container then protected its old image
from every retention sweep. Cleanup now:

- removes application containers whose `meghify.application` label no longer
  matches an application record, then
- removes the matching images, and
- includes label-less tags that live in an application repository the panel
  has already stamped.

This is how the old `roopsa-web` image with a different application-ID prefix
is reclaimed. `IMAGE_KEEP` still controls how many images a **live**
application keeps; the default is `1`. If your `.env` explicitly sets
`IMAGE_KEEP=2`, change it to `1` to drop the previous release as well.

## Uninstall leaves a fresh Docker host

`meghify uninstall` and `install.sh --uninstall` now remove every Docker
resource Meghify created, not just the panel directory:

- application, database, service, proxy, sandbox, terminal and build-helper
  containers;
- application and service Compose projects;
- managed and Compose volumes, including application/database data, the
  build-cache volume, proxy configuration and TLS certificates;
- managed and application/service networks;
- application images (including old tags), plus the panel, helper, proxy,
  sandbox and terminal images;
- Docker build cache.

The Docker engine itself and unrelated projects stay. The operation is
destructive; back up application data first.

## Verification

`go test -count=1 ./...`, `go vet ./...`, `go build ./...`, `go build -tags
web_assets ./...`, `npm run typecheck` and `npm run build` pass. Docker runtime
validation (sandbox stop/restart and uninstall cleanup) still requires a
Docker-capable host.
