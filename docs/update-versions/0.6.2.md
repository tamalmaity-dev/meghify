# v0.6.2 — hot file-provider routing; faster builds on small nodes

**Released:** 2026-10-18 · **Commit:** *see the tag* · **Tag:** `v0.6.2`

Two problems the field report on a 2-core VPS exposed: the domain kept
answering the proxy's bare `404 page not found` while the deployment was stuck
building, and builds dragged under the sandbox cap until the deploy timeout
killed them. The code audit traced both, and this release fixes the routing
problem at its root (Dokploy-style dynamic configuration) plus the two knobs
that made small-node builds slow.

## Update

```bash
meghify update
```

The running proxy carries the previous flags, so the first deployment (or
panel restart) after updating **recreates the proxy once** — the log says
"upgrading the proxy for dynamic file routing". Certificates (ACME) live in
their own volume and survive. After that, domain edits apply without
redeploys.

## What changed

### Domain routing is a dynamic config file per application

Routing no longer rides container labels. The panel drafts one Traefik file
per application (routers, per-domain services, gzip, robots header,
redirects, the `letsencrypt` resolver where configured), writes it through the
Docker API into the proxy's `meghify-proxy-cfg` volume, and rewrites it:

- **immediately on every domain edit** — path, port, protocol, redirect,
  robots toggles go live while the app keeps running (Dokploy's model);
- after every deployment, success or failure;
- at every panel boot, from the database.

Routers address the application container by its **stable name** on the shared
proxy network, so a rolling release — or a failed-release revert, which v0.6.1
introduced — needs no routing change at all.

A missing container behind a route now answers Traefik's honest
`502 Bad Gateway` instead of the label-orphan `404 page not found`.

### Builds get a whole two-core node

The build sandbox capped builds at half of the node (1 core on a 2-core VPS),
which alone could push a cold nixpacks build past the 30-minute deploy
timeout. Unset limits now reserve **half of the node but at least two cores**,
so two-core machines build with both cores — the panel idles at a few percent
and one build runs at a time regardless. Explicit `BUILD_CPU_LIMIT` /
`BUILD_MEMORY_LIMIT` overrides are now enforced too: a sandbox whose limits
no longer match them is recreated at the next deployment, keeping the build
cache volume.

### Default deploy timeout: 30m → 45m

The extra headroom covers a first (cache-cold) build on a small node. The
timeout message at boot prints the value; `DEPLOY_TIMEOUT` still overrides it.

## Internals

- `internal/deploy/dynamic.go` — the router generator, the Docker-API upload,
  boot reconciliation (`ReconcileRoutes`), cleared apps leave a comments-only
  stub (standalone empty sections are rejected by Traefik's file decoder and
  would poison every route in the directory).
- The proxy runs with `--providers.file.directory=/etc/traefik/dynamic` and
  the `meghify-proxy-cfg` named volume; a `meghify.gen` label triggers the
  one-time recreation of an older proxy.
- Applications keep only metadata labels; the Networking card shows the
  routing configuration the proxy serves.
